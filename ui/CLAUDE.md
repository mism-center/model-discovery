## Project Overview

MDSC Portal is a Multiscale Immune Systems Modeling (MISM) portal built with React Router 7 and TypeScript. It provides a search interface for multiscale model exploration.

## Tech Stack

- **Framework**: React Router 7 with server-side rendering (SSR) enabled
- **React**: v19
- **TypeScript**: v5.9
- **Styling**: TailwindCSS v4 with custom theme plugin
- **Component Library**: HeroUI v2.8 (custom UI library)
- **Build Tool**: Vite v7
- **Linting**: ESLint v9 with typescript-eslint, Prettier, jsx-a11y, and unicorn plugins
- **Formatting**: Prettier v3.8

## Development Commands

```bash
# Development server with HMR at http://localhost:5173
npm run dev

# Production build (outputs to build/ directory)
npm run build

# Start production server
npm start

# Type checking (generates types and runs tsc)
npm run typecheck

# Linting
npm run lint
npm run lint:fix

# Code formatting
npm run format
```

## Architecture

### File-Based Routing

Routes are defined in `app/routes.ts` using React Router's configuration format:

- Route components live in `app/routes/`
- Each route can export `meta()`, `loader()`, `action()`, and default component
- Route types are auto-generated in `app/routes/+types/` directories

### Global Layout

The `app/root.tsx` file defines the global layout structure:

- **Layout**: Wraps the entire app with HTML/head/body structure
- **Providers**: Includes HeroUIProvider with React Router navigation integration
- **ErrorBoundary**: Global error handling with dev stack traces
- Header and Footer are included in the root layout and appear on all pages

### Component Organization

```
app/components/
├── layout/        # Global layout components (Header, Footer, Breadcrumbs)
└── sections/      # Feature-specific components organized by domain
    └── search/    # Search-related components (SearchBar, SearchSidebar, etc.)
```

### Styling Architecture

- **TailwindCSS v4**: Uses the new `@import "tailwindcss"` syntax in `app/styles/index.css`
- **Custom Plugin**: `app/styles/hero.ts` extends Tailwind with custom utilities
- **HeroUI Integration**: Component library sources are configured in the `@source` directive
- **Theme**: Uses "light" mode by default with Open Sans as the primary font
- **Responsive**: Uses `min-h-dvh` (dynamic viewport height) for mobile compatibility

### TypeScript Configuration

- Path aliases configured via `vite-tsconfig-paths` plugin
- Strict type checking enabled
- Route types auto-generated by React Router Dev

### Vite Plugins

The project uses several Vite plugins in `vite.config.ts`:

1. `@tailwindcss/vite` - Tailwind v4 Vite integration
2. `@react-router/dev/vite` - React Router build plugin
3. `vite-tsconfig-paths` - TypeScript path mapping
4. `vite-plugin-svgr` - SVG as React components

## Key Conventions

### Route Components

Routes should export:

- `meta()` function for SEO metadata
- Default export for the component
- Optional `loader()` for data fetching
- Optional `action()` for mutations

### Component Patterns

- Use HeroUI components for UI elements
- TailwindCSS utility classes for styling
- Prefer functional components with TypeScript

### ESLint Rules

- Follows recommended configs for TypeScript, React, and Prettier
- jsx-a11y enabled for accessibility checking
- Unicorn plugin enabled with `prevent-abbreviations` disabled
- React runtime configured (no need to import React)

## Deployment

The build outputs to `build/` with two directories:

- `build/client/` - Static assets for client-side
- `build/server/` - Server-side rendering code

Deploy the built app using the Node server: `npm start` runs the production server.
